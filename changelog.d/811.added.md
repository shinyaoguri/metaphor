- Colors can be taken apart again: `Color` gained `hue` / `saturation` /
  `brightness` properties (the inverse of `Color(hue:saturation:brightness:alpha:)`,
  which previously only converted HSB → RGB), and seven Processing-named free
  functions read a `Color` — `hue(_:)`, `saturation(_:)`, `brightness(_:)`,
  `alpha(_:)`, `red(_:)`, `green(_:)` and `blue(_:)`
  ([#811](https://github.com/shinyaoguri/metaphor/issues/811))
  - **The results are on a 0–1 scale and ignore `colorMode()`**, unlike
    Processing, where the extractors follow the current mode. They take a
    `Color`, and `Color` values are normalized everywhere in metaphor. Porting
    `colorMode(HSB, 360, 100, 100)` code means scaling by hand (`hue(c) * 360`),
    and `fill(red(c), green(c), blue(c))` compiles but draws almost black under
    the default 0–255 mode — pass the `Color` to `fill(_:)` instead
  - Swift does not keep functions and variables in separate namespaces, so a
    local named `hue` (or `red`, `alpha`, …) shadows the free function inside its
    scope. Use the matching `Color` property (`c.hue`, `c.r`, …) there
  - `blendColor()` is still missing and is tracked separately in
    [#1153](https://github.com/shinyaoguri/metaphor/issues/1153)
