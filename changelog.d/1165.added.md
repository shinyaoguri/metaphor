- `textWrap(_ mode: TextWrap)` and `textBounds(_ string:_ x:_ y:) -> TextBounds`, the last two
  gaps in the p5.js typography set ([#1165](https://github.com/shinyaoguri/metaphor/issues/1165)):

  ```swift
  textWrap(.char)
  text("filling every line", 20, 20, 120, 200)

  let b = textBounds("metaphor", 40, 80)
  rect(b.x, b.y, b.width, b.height)
  ```

  - `textWrap()` picks where the **rectangle form** of `text()` may break a line. `.word` is the
    default and is exactly what metaphor already did, so no existing sketch changes. `.char` fills
    every line to the edge of the box. Neither rule affects `text(_:_:_:)`, which breaks only at
    the newlines in the string, and `.word` prefers word boundaries rather than promising never to
    split a word — a word longer than the box is still broken between characters under both rules.
  - `textBounds()` returns the box `text()` would fill, already accounting for `textAlign()`,
    `textSize()`, `textFont()`, `textStyle()` and, for a string with newlines, `textLeading()`.
  - **The width is the advance sum `textWidth()` reports, not the extent of the ink**, so
    `textBounds(s, x, y).width == textWidth(s)` holds. That is the ruler `text()` lays glyphs out
    with and `textAlign()` aligns against (#802 / #803), so a box measured here and a string placed
    with `textAlign()` agree. It differs from p5.js, which measures the ink and therefore returns a
    box a touch tighter than its own `textWidth()`: glyphs such as `f`, or an italic face, can
    paint a little past either edge here.
  - The height is `textAscent()` + `textDescent()` — a property of the font, not of the string —
    plus one `textLeading()` per newline, so `"x"` and `"X"` get boxes of the same height.
  - `textWrap()` is 2D style state: saved and restored by `push()` / `pop()` and `pushStyle()` /
    `popStyle()`, and kept across frames.
