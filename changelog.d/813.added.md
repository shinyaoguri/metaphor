- 2D shapes gained the three Processing calls that were still missing, and the number of segments
  a cubic Bézier is drawn with is now one setting instead of two
  ([#813](https://github.com/shinyaoguri/metaphor/issues/813)):
  - `quadraticVertex(cx, cy, x, y)` — a quadratic Bézier vertex, promoted to the equivalent cubic
    (as in Processing and p5.js), so you no longer have to convert the control point by hand.
  - `bezierDetail(n)` — the counterpart of `curveDetail(n)`. **This changes what `bezier()` draws.**
    It used to be fixed at 24 segments while `beginShape()` + `bezierVertex()` followed
    `curveDetail()` (20 by default), so the same curve came out at two different resolutions and
    `curveDetail()` had no effect on `bezier()`. Both now follow `bezierDetail()`, whose default is
    **20** — matching `curveDetail()` and Processing. `bezier()` therefore draws 20 segments rather
    than 24 unless you ask for more; call `bezierDetail(24)` to keep the old look. As in Processing,
    `curveDetail()` is now for `curve()` / `curveVertex()` only and no longer affects
    `bezierVertex()`.
  - `shapeMode(_ mode: ShapePositionMode)` — `.corner` (the default, unchanged behaviour),
    `.corners` and `.center` for `shape(s, x, y, w, h)` on a 2D shape, alongside the existing
    `rectMode()` / `ellipseMode()` / `imageMode()`. The enum is named `ShapePositionMode` because
    `ShapeMode` already names the primitive kind passed to `beginShape()`.

  Both new settings are 2D style state: saved and restored by `push()` / `pop()` and
  `pushStyle()` / `popStyle()`, and kept across frames.
