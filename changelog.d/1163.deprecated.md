- `VertexLayout.position` and `VertexLayout.positionColor` are deprecated and will be removed in
  the minor release **after** the one that publishes this warning
  ([#1163](https://github.com/shinyaoguri/metaphor/issues/1163)). Nothing in the library, the
  examples, or any known consumer has ever built a pipeline with either case, and no Swift vertex
  struct writes those bytes — so unlike the other five cases there is nothing to check the layout
  against, and no material to decide what it was meant to be. The five layouts the renderer
  actually uses (`positionNormalColor`, `positionNormalUV`, `position2DColor`,
  `position2DTexCoordColor`, `position2DOnly`) are unaffected.

  Nothing becomes impossible: `PipelineFactory.vertexDescriptor(_:)` already accepts any
  `MTLVertexDescriptor`, so both layouts can be built by hand and passed straight through.

  | Deprecated | Use instead |
  |---|---|
  | `.vertexLayout(.position)` | `.vertexDescriptor(descriptor)` with the four lines below |
  | `.vertexLayout(.positionColor)` | `.vertexDescriptor(descriptor)` with the eight lines below |

  ```swift
  // .position — a plain [SIMD3<Float>] buffer
  let descriptor = MTLVertexDescriptor()
  descriptor.attributes[0].format = .float3
  descriptor.attributes[0].offset = 0
  descriptor.attributes[0].bufferIndex = 0
  descriptor.layouts[0].stride = 16

  // .positionColor — a { SIMD3<Float>; SIMD4<Float> } buffer
  descriptor.attributes[1].format = .float4
  descriptor.attributes[1].offset = 16
  descriptor.attributes[1].bufferIndex = 0
  descriptor.layouts[0].stride = 32
  ```

  Note that neither layout ever described `Vertex3D`, whose stride is 48 and whose color starts at
  byte 32; feeding a `[Vertex3D]` buffer through `.positionColor` reads the normal as the color.
