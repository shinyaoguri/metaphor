- Allocating a GPU buffer with a very large element count now fails the way the
  API says it does, instead of taking the process down. `createBuffer(count:type:)`
  returns `GPUBuffer?` and documents `nil` on failure, but
  `MemoryLayout<T>.stride * count` was computed *before* the guard, so a large
  `count` trapped with `Swift runtime failure: arithmetic overflow` and never
  reached the `nil` return — a `guard let` at the call site could not protect
  against it. The multiplication now happens inside the guard via
  `multipliedReportingOverflow(by:)`. `createParticleSystem(count:)` had the same
  shape and now throws `MetaphorError.particle(.bufferCreationFailed)` for counts
  that would overflow, matching its existing contract. Sizes that are merely too
  large to allocate keep returning `nil` / throwing as before
  ([#1091](https://github.com/shinyaoguri/metaphor/issues/1091))
