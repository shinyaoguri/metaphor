- `textStyle(_ style: TextStyle)` — the p5.js counterpart, with `.normal`, `.bold`, `.italic` and
  `.boldItalic` ([#816](https://github.com/shinyaoguri/metaphor/issues/816)). It keeps the current
  family and asks Core Text for that family's bold or italic face, so unlike a style-qualified name
  the same code ports between fonts:

  ```swift
  textFont("Helvetica Neue")
  textStyle(.bold)
  ```

  - **A font with no face for the style requested is drawn unstyled, with a warning naming it.**
    metaphor never substitutes a different font to satisfy the style — Monaco, Geneva and Papyrus
    have no bold or italic face at all. This is the difference from writing the style into the
    name: `textFont("Papyrus Bold")` silently draws in **Helvetica**, losing the family as well as
    the style, because Core Text answers a name it cannot resolve with the system default.
  - `.normal` means "use the face the font name selects", not "strip bold", so it leaves a
    style-qualified `textFont()` name alone — `textFont("Helvetica Neue Bold")` still draws bold
    under the default `.normal`. Nothing about existing sketches changes.
  - The style is re-applied when the font changes, so `textFont()` after `textStyle()` keeps the
    style. Unlike `textSize()` and `textFont()` it does not reset `textLeading()`.
  - It is 2D style state: saved and restored by `push()` / `pop()` and `pushStyle()` /
    `popStyle()`, and kept across frames.
  - `textWrap()` and `textBounds()`, listed alongside `textStyle()` in the original report, are
    tracked separately in [#1165](https://github.com/shinyaoguri/metaphor/issues/1165).
